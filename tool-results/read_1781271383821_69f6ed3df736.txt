    57→### MEJORA sesion 19: Air Intra Batched Sync (evita timeout de Vercel)
    58→- **Problema:** El sync completo de Air Intra (~7,500 productos, 16 paginas de 500) puede tardar 30-60+ segundos, excediendo el limite de 60s de Vercel Hobby plan para serverless functions
    59→- **Solucion:** Sync por lotes (batched) - divide la sincronizacion en chunks de 4 paginas (~2,000 productos, ~10-15s por lote)
    60→- **Arquitectura:**
    61→  1. Primer call: Login + lote 1 (paginas 0-3). Retorna `hasMore: true`, `nextPage: 4`, `token`, `exchangeRate`
    62→  2. Calls subsiguientes: Frontend envia `batch: { startPage, endPage, token, exchangeRate }` para cada lote
    63→  3. Finalize step: Despues de todos los lotes, frontend envia `batch: { token, exchangeRate, finalize: true }` que ejecuta syp sync, recategorizacion, recovery, y actualiza lastSyncAt
    64→- **Backend:** `syncAirIntraBatch()` y `syncAirIntraFinalize()` en `src/app/api/admin/suppliers/sync/route.ts`
    65→- **Frontend:** `handleSync()` en `src/app/admin/proveedores/page.tsx` - orquesta los lotes automaticamente con barra de progreso
    66→- **vercel.json:** `maxDuration` corregido a 60 (antes decia 300, pero Hobby plan limita a 60s)
    67→- **PAGES_PER_BATCH:** 4 (constante, 4 x 500 = 2,000 productos por lote)
    68→- **Compatibilidad:** Invid y Elit siguen usando sync completo (no necesitan batched, son mas chicos)
    69→

   202→
   203→### Formulas de Precio
   204→```
   205→Precio de lista  = costUSD x (1 + ivaRate/100) x (1 + markup/100) x cotizacionDolar
   206→Precio efectivo  = costUSD x (1 + ivaRate/100) x (1 + (markup - cashDiscount)/100) x cotizacionDolar
   207→Precio oferta    = salePrice (si esta dentro del rango de fechas, reemplaza precio de lista)
   208→```
   209→Donde markup, cashDiscount e ivaRate siguen prioridad: Producto individual → Categoría (heredando de padre si no tiene) → Global/Default.

   287→### Sistema de Filtrado de Productos (3 capas - FIX PERMANENTE)
   288→El PC Builder usa **3 capas de defensa** para garantizar que solo productos correctos aparezcan en cada slot:
   289→
   290→| Capa | Mecanismo | Descripcion |
   291→|------|-----------|-------------|
   292→| **1. Inclusion (Whitelist)** | `BUILDER_INCLUDE_PATTERNS` | Cada slot define que palabras clave DEBE tener el nombre del producto (ej: GPU requiere "RTX/GTX/RADEON"). Si no coincide con NINGUN patron, no aparece. **Es la defensa principal: funciona incluso si la categoria en la DB esta mal** |
   293→| **2. Exclusion (Blacklist)** | `BUILDER_EXCLUDE_PATTERNS` | Patrones que excluyen productos no deseados (notebooks en GPU, discos externos en SSD, etc.) |
   294→| **3. Compatibilidad** | `applyCompatibilityFilters` | Filtra por socket (CPU->Mother), DDR (Mother->RAM), wattaje (GPU->PSU) |
   295→
   296→### Por que se desordenaba antes (Causa raiz resuelta)
   297→El problema recurrente tenia 3 causas encadenadas:
   298→1. **Sync categorizaba mal**: El `CATEGORY_KEYWORD_MAP` chequeaba keywords de componentes (RTX, DDR, SSD) ANTES que productos completos (NOTEBOOK, PC ARMADAS). "NOTEBOOK RTX 4060" coincidia con "RTX" primero -> placas-de-video
   299→2. **PC Builder no validaba nombres**: Solo usaba categoria de DB + blacklist chica. No verificaba que el producto realmente fuera lo que dice la categoria
   300→3. **Cada sync traia productos nuevos mal categorizados**: Aunque corrijas manualmente, la proxima sync "contaminaba" otra vez
   301→
   302→### Solucion permanente (implementada sesion 3)
   303→1. **Whitelist en PC Builder**: `BUILDER_INCLUDE_PATTERNS` - cada slot valida el nombre del producto en runtime
   304→2. **Keywords ordenadas en sync**: Productos completos (NOTEBOOK, PC ARMADAS) se chequean ANTES que componentes (RTX, DDR, SSD)
   305→3. **Validacion post-sync automatica**: Despues de cada sync, se corrigen automaticamente productos mal categorizados en TODAS las categorias del PC Builder

   328→### Deteccion de Socket (FIX sesion 16)
   329→- **Bug:** Intel Core Ultra 5 225F con "LGA1851" (sin espacio) en el nombre era detectado como Socket LGA 1700, bloqueando todas las mothers LGA 1851 compatibles
   330→- **Causa raiz:** El regex `/\bS?1851\b/` no matcheaba "LGA1851" porque `\b` no detecta boundary entre "A" y "1" (ambos son word chars). Al fallar, el fallback asignaba "1700" por defecto a todos los Intel

   332→- **Fix 2 - Intel Core Ultra:** Agregada deteccion por modelo: si el nombre contiene "CORE ULTRA", siempre se asigna socket 1851 (Arrow Lake). Se ejecuta antes del fallback a 1700

   611→## Protecciones contra Deploy de Versiones Viejas (IMPLEMENTADO sesion 7)
   612→
   613→### Problema que resolvio
   614→Se pusheo una version vieja del codigo que sobreescribio la version correcta en produccion. La causa raiz fue una carpeta `compucity-repo/` duplicada dentro del proyecto que apuntaba al mismo remote de GitHub.
   615→
   616→### Capa 1: Pre-push hook
   617→- **Archivo:** `githooks/pre-push` (configurado via `git config core.hooksPath githooks`)
   618→- **Funcion:** Antes de cada `git push`, verifica que el local no este atras del remoto
   619→- **Si el local esta atras:** Bloquea el push y muestra instrucciones para hacer `git pull --rebase origin main`
   620→- **Si hay divergencia:** Tambien bloquea y sugiere rebase
   621→
   622→### Capa 2: Script de deploy seguro
   623→- **Archivo:** `scripts/deploy.sh`
   624→- **Uso:** `bash scripts/deploy.sh "mensaje del commit"`
   625→- **Verificaciones:** Rama correcta, fetch remoto, comparar commits, verificar cambios pendientes, solo pushea si todo esta OK
   626→
   627→### Capa 3: Eliminacion del repo duplicado
   628→- **Accion:** Se elimino la carpeta `compucity-repo/` que causaba confusion
   629→- **Proteccion:** Se agrego `compucity-repo/` al `.gitignore` para prevenir recrearlo accidentalmente
   630→
   631→### Workflow recomendado
   632→1. Siempre hacer `git pull --rebase origin main` antes de trabajar
   633→2. Hacer cambios, probar localmente
   634→3. Usar `bash scripts/deploy.sh "feat: descripcion"` para pushear de forma segura
   635→4. Vercel se actualiza automaticamente con el push
