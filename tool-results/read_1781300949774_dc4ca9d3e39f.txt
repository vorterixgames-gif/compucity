    58→    58→    58→### MEJORA sesion 19: Air Intra Batched Sync (evita timeout de Vercel)
    59→    59→    59→- **Problema:** El sync completo de Air Intra (~7,500 productos, 16 paginas de 500) puede tardar 30-60+ segundos, excediendo el limite de 60s de Vercel Hobby plan para serverless functions
    60→    60→    60→- **Solucion:** Sync por lotes (batched) - divide la sincronizacion en chunks de 4 paginas (~2,000 productos, ~10-15s por lote)
    61→    61→    61→- **Arquitectura:**
    62→    62→    62→  1. Primer call: Login + lote 1 (paginas 0-3). Retorna `hasMore: true`, `nextPage: 4`, `token`, `exchangeRate`
    63→    63→    63→  2. Calls subsiguientes: Frontend envia `batch: { startPage, endPage, token, exchangeRate }` para cada lote
    64→    64→    64→  3. Finalize step: Despues de todos los lotes, frontend envia `batch: { token, exchangeRate, finalize: true }` que ejecuta syp sync, recategorizacion, recovery, y actualiza lastSyncAt
    65→    65→    65→- **Backend:** `syncAirIntraBatch()` y `syncAirIntraFinalize()` en `src/app/api/admin/suppliers/sync/route.ts`
    66→    66→    66→- **Frontend:** `handleSync()` en `src/app/admin/proveedores/page.tsx` - orquesta los lotes automaticamente con barra de progreso
    67→    67→    67→- **vercel.json:** `maxDuration` corregido a 60 (antes decia 300, pero Hobby plan limita a 60s)
    68→    68→    68→- **PAGES_PER_BATCH:** 4 (constante, 4 x 500 = 2,000 productos por lote)
    69→    69→    69→- **Compatibilidad:** Invid y Elit siguen usando sync completo (no necesitan batched, son mas chicos)

   199→   199→   199→- **Campos:** `salePrice REAL`, `saleStart TEXT`, `saleEnd TEXT` en tabla products
   200→   200→   200→- **Logica:** Si salePrice > 0 y estamos dentro del rango de fechas, se muestra como precio de oferta

   203→   203→   203→
   204→   204→   204→### Formulas de Precio
   205→   205→   205→```
   206→   206→   206→Precio de lista  = costUSD x (1 + ivaRate/100) x (1 + markup/100) x cotizacionDolar
   207→   207→   207→Precio efectivo  = costUSD x (1 + ivaRate/100) x (1 + (markup - cashDiscount)/100) x cotizacionDolar
   208→   208→   208→Precio oferta    = salePrice (si esta dentro del rango de fechas, reemplaza precio de lista)
   209→   209→   209→```
   210→   210→   210→Donde markup, cashDiscount e ivaRate siguen prioridad: Producto individual → Categoría (heredando de padre si no tiene) → Global/Default.

   288→   288→   288→### Sistema de Filtrado de Productos (3 capas - FIX PERMANENTE)
   289→   289→   289→El PC Builder usa **3 capas de defensa** para garantizar que solo productos correctos aparezcan en cada slot:
   290→   290→   290→
   291→   291→   291→| Capa | Mecanismo | Descripcion |
   292→   292→   292→|------|-----------|-------------|
   293→   293→   293→| **1. Inclusion (Whitelist)** | `BUILDER_INCLUDE_PATTERNS` | Cada slot define que palabras clave DEBE tener el nombre del producto (ej: GPU requiere "RTX/GTX/RADEON"). Si no coincide con NINGUN patron, no aparece. **Es la defensa principal: funciona incluso si la categoria en la DB esta mal** |
   294→   294→   294→| **2. Exclusion (Blacklist)** | `BUILDER_EXCLUDE_PATTERNS` | Patrones que excluyen productos no deseados (notebooks en GPU, discos externos en SSD, etc.) |
   295→   295→   295→| **3. Compatibilidad** | `applyCompatibilityFilters` | Filtra por socket (CPU->Mother), DDR (Mother->RAM), wattaje (GPU->PSU) |

   297→   297→   297→### Por que se desordenaba antes (Causa raiz resuelta)
   298→   298→   298→El problema recurrente tenia 3 causas encadenadas:
   299→   299→   299→1. **Sync categorizaba mal**: El `CATEGORY_KEYWORD_MAP` chequeaba keywords de componentes (RTX, DDR, SSD) ANTES que productos completos (NOTEBOOK, PC ARMADAS). "NOTEBOOK RTX 4060" coincidia con "RTX" primero -> placas-de-video
   300→   300→   300→2. **PC Builder no validaba nombres**: Solo usaba categoria de DB + blacklist chica. No verificaba que el producto realmente fuera lo que dice la categoria
   301→   301→   301→3. **Cada sync traia productos nuevos mal categorizados**: Aunque corrijas manualmente, la proxima sync "contaminaba" otra vez
   302→   302→   302→
   303→   303→   303→### Solucion permanente (implementada sesion 3)
   304→   304→   304→1. **Whitelist en PC Builder**: `BUILDER_INCLUDE_PATTERNS` - cada slot valida el nombre del producto en runtime
   305→   305→   305→2. **Keywords ordenadas en sync**: Productos completos (NOTEBOOK, PC ARMADAS) se chequean ANTES que componentes (RTX, DDR, SSD)
   306→   306→   306→3. **Validacion post-sync automatica**: Despues de cada sync, se corrigen automaticamente productos mal categorizados en TODAS las categorias del PC Builder

   329→   329→   329→### Deteccion de Socket (FIX sesion 16)
   330→   330→   330→- **Bug:** Intel Core Ultra 5 225F con "LGA1851" (sin espacio) en el nombre era detectado como Socket LGA 1700, bloqueando todas las mothers LGA 1851 compatibles
   331→   331→   331→- **Causa raiz:** El regex `/\bS?1851\b/` no matcheaba "LGA1851" porque `\b` no detecta boundary entre "A" y "1" (ambos son word chars). Al fallar, el fallback asignaba "1700" por defecto a todos los Intel
   332→   332→   332→- **Fix 1 - Regex:** Cambiado a `/(?:S|LGA\s*)?1851/` que matchea S1851, LGA 1851, LGA1851 y 1851 standalone. Mismo fix para 1700
   333→   333→   333→- **Fix 2 - Intel Core Ultra:** Agregada deteccion por modelo: si el nombre contiene "CORE ULTRA", siempre se asigna socket 1851 (Arrow Lake). Se ejecuta antes del fallback a 1700
