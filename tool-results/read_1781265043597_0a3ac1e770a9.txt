   609→## Protecciones contra Deploy de Versiones Viejas (IMPLEMENTADO sesion 7)
   610→
   611→### Problema que resolvio
   612→Se pusheo una version vieja del codigo que sobreescribio la version correcta en produccion. La causa raiz fue una carpeta `compucity-repo/` duplicada dentro del proyecto que apuntaba al mismo remote de GitHub.
   613→
   614→### Capa 1: Pre-push hook
   615→- **Archivo:** `githooks/pre-push` (configurado via `git config core.hooksPath githooks`)
   616→- **Funcion:** Antes de cada `git push`, verifica que el local no este atras del remoto
   617→- **Si el local esta atras:** Bloquea el push y muestra instrucciones para hacer `git pull --rebase origin main`
   618→- **Si hay divergencia:** Tambien bloquea y sugiere rebase
   619→
   620→### Capa 2: Script de deploy seguro
   621→- **Archivo:** `scripts/deploy.sh`
   622→- **Uso:** `bash scripts/deploy.sh "mensaje del commit"`
   623→- **Verificaciones:** Rama correcta, fetch remoto, comparar commits, verificar cambios pendientes, solo pushea si todo esta OK
   624→
   625→### Capa 3: Eliminacion del repo duplicado
   626→- **Accion:** Se elimino la carpeta `compucity-repo/` que causaba confusion
   627→- **Proteccion:** Se agrego `compucity-repo/` al `.gitignore` para prevenir recrearlo accidentalmente
   628→
   629→### Workflow recomendado
   630→1. Siempre hacer `git pull --rebase origin main` antes de trabajar
   631→2. Hacer cambios, probar localmente
   632→3. Usar `bash scripts/deploy.sh "feat: descripcion"` para pushear de forma segura
   633→4. Vercel se actualiza automaticamente con el push
